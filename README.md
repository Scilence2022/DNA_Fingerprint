# FGR2 - Fast Genome Representation

FGR2 is a high-performance tool for extracting fingerprints of DNA data storage. It efficiently processes both FASTA and FASTQ files, including their gzipped variants.

> ### :warning: Important correctness notice (v2.1.0)
>
> Versions before 2.1.0 contained two defects in the fingerprint generator that
> corrupted every `.fgr2` file they produced:
>
> 1. **k-mer reconstruction** — the hash-table key was built without stripping the
>    sub-table suffix, so the emitted k-mer *sequences* did not occur in the input at
>    all, and the 64-bit key silently truncated (merging distinct k-mers).
> 2. **Bottom-N selection** — the max-heap compared the wrong child, so the selected
>    k-mers were **not** the N with minimal hash values, i.e. not a valid MinHash sketch.
>
> Both are fixed in 2.1.0. **Fingerprints generated by earlier versions should be
> regenerated**; similarity matrices and trees derived from them are not reliable.
> `make check` verifies both properties.

## Features

- Fast k-mer counting and analysis
- Support for both FASTA and FASTQ formats (including gzipped files)
- Multi-threaded processing for improved performance
- Automatic coverage threshold detection
- Flexible output options including k-mer histograms
- Choice of hash functions (MurmurHash3 or Thomas Wang's hash)

## Installation

### Prerequisites

- C compiler (GCC recommended)
- zlib development library
- make

### Building from Source

```bash
git clone https://github.com/Scilence2022/DNA_Fingerprint.git
cd DNA_Fingerprint
make                 # builds fgr2
make check           # runs the regression test suite
sudo make install    # optional: installs to /usr/local/bin (override with PREFIX=)
```

For the Python analysis tool:

```bash
pip install -r requirements.txt
```

Other make targets:

| Target | Description |
|---|---|
| `make` | Build `fgr2` (the supported tool) |
| `make check` | Run the regression test suite |
| `make debug` | Rebuild with `-O0 -g` and ASan/UBSan |
| `make legacy` | Build the deprecated `fgr` (superseded by `fgr2`) |
| `make install` | Install to `$(PREFIX)/bin` (default `/usr/local`) |
| `make clean` | Remove build artefacts |

## Usage

```bash
fgr2 [options] <in.fa|in.fq|in.fa.gz|in.fq.gz>
```

### Options

- `-k INT`     k-mer size [default: 31]
- `-p INT`     prefix length [default: 14]
- `-b INT`     block size [default: 10000000]
- `-t INT`     number of worker threads [default: 4]
- `-N INT`     number of k-mers to output [default: 10000]
- `-c INT`     minimum coverage threshold [default: auto-detect]
- `-w`         use Thomas Wang's hash function (default: MurmurHash3)
- `-o FILE`    Output file for top N k-mers and coverage histogram

### Input Formats

FGR2 supports the following input formats:
- FASTA format (*.fa, *.fa.gz)
- FASTQ format (*.fq, *.fq.gz)

### Output Files

When using the `-o` option, FGR2 generates two files:
1. The specified output file containing the top N k-mers with minimal hash values
2. A histogram file (*.hist) containing k-mer coverage distribution

## Examples

### Basic Usage

```bash
# Process a FASTA file with default settings
fgr2 input.fa

# Process a gzipped FASTQ file with custom k-mer size
fgr2 -k 25 input.fq.gz

# Process with custom coverage threshold
fgr2 -c 10 input.fa

# Save results to specific output file
fgr2 -o results.txt input.fa
```

### Advanced Usage

```bash
# Use multiple threads and custom block size
fgr2 -t 8 -b 20000000 input.fa

# Use Thomas Wang's hash function
fgr2 -w input.fa

# Output top 1000 k-mers with custom coverage
fgr2 -N 1000 -c 5 input.fa
```

## Output Format

### K-mer Output File

The fingerprint file contains a self-describing metadata header, a column header,
and then one k-mer per line sorted by ascending hash value:

```
#fgr2	version=2.1.0	k=31	N=10000	hash=murmurhash3	coverage_threshold=2	n_kmers=10000
#kmer	hash	coverage
ATCGATCGATCGATCGATCGATCGATCGATC	503339280888316	15
GCTAGCTAGCTAGCTAGCTAGCTAGCTAGCT	772672121748907	22
...
```

- Lines beginning with `#` are comments/metadata.
- Record format: `<sequence>\t<hash_value>\t<coverage>`
- `calculate_similarity.py` reads the metadata header to verify that sketches being
  compared were built with the same `k` and hash function.

If `-o` is omitted the fingerprint is written to **stdout** and all status messages
and the histogram go to **stderr**, so redirection produces a clean file:

```bash
fgr2 -k 31 -N 10000 input.fa > sample.fgr2
```

### Histogram File

The histogram file (*.hist) contains:
- Coverage distribution data
- Format: `<coverage>\t<number_of_kmers>`
- Written to `<output>.hist` when `-o` is used, otherwise to stderr.

## Performance Considerations

- Increase `-t` for better performance on multi-core systems
- Adjust `-b` based on available memory
- Larger `-k` values require more memory but may provide better specificity
