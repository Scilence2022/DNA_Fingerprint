# Supplementary Materials

## Efficient DNA Fingerprinting for Large-Scale Sequence Comparison and Phylogenetic Analysis

### Supplementary Methods

#### S1. Detailed Hash Function Implementations

**S1.1 MurmurHash3 Implementation**

The MurmurHash3 algorithm is implemented with the following constants and operations:

```c
const uint64_t c1 = 0x87c37b91114253d5ULL;
const uint64_t c2 = 0x4cf5ad432745937fULL;

// Mixing function
static inline uint64_t fmix64(uint64_t k) {
    k ^= k >> 33;
    k *= 0xff51afd7ed558ccdULL;
    k ^= k >> 33;
    k *= 0xc4ceb9fe1a85ec53ULL;
    k ^= k >> 33;
    return k;
}
```

The algorithm processes 8-byte blocks with rotation and mixing operations to ensure uniform distribution of hash values across the 64-bit space.

**S1.2 Wang Hash Implementation**

Thomas Wang's 64-bit integer hash function uses a series of reversible operations:

```c
static inline uint64_t hash_wang(uint64_t key) {
    key = (~key) + (key << 21);
    key = key ^ (key >> 24);
    key = (key + (key << 3)) + (key << 8);
    key = key ^ (key >> 14);
    key = (key + (key << 2)) + (key << 4);
    key = key ^ (key >> 28);
    key = key + (key << 31);
    return key;
}
```

**S1.3 Invertible Hash Function**

The hash64/hash64i pair provides bijective mapping for k-mer distribution:

```c
// Forward hash
static inline uint64_t hash64(uint64_t key, uint64_t mask) {
    key = (~key + (key << 21)) & mask;
    key = key ^ key >> 24;
    key = ((key + (key << 3)) + (key << 8)) & mask;
    key = key ^ key >> 14;
    key = ((key + (key << 2)) + (key << 4)) & mask;
    key = key ^ key >> 28;
    key = (key + (key << 31)) & mask;
    return key;
}
```

#### S2. K-mer Encoding and Canonical Form

**S2.1 Nucleotide Encoding**

DNA bases are encoded using 2-bit representation:
- A: 00
- C: 01
- G: 10
- T: 11

Non-ACGT characters are encoded as 4 (100 in binary) and trigger k-mer restart.

**S2.2 Canonical K-mer Selection**

For each k-mer position, we compute:
1. Forward k-mer: direct encoding of sequence
2. Reverse complement: bit-wise complement with reversal
3. Canonical form: lexicographically smaller of the two

```
Example for k=3:
Sequence: ACG
Forward:  000110 (ACG)
RevComp:  011011 (CGT)
Canonical: 000110 (ACG, smaller)
```

#### S3. Multi-threading Architecture

**S3.1 Pipeline Stages**

The three-stage pipeline uses double buffering to overlap I/O and computation:

```
Stage 1 (I/O bound):     [Read][    ][Read][    ]
Stage 2 (CPU bound):     [    ][Proc][    ][Proc]
Stage 3 (Memory bound):  [    ][    ][Inst][    ]
```

**S3.2 Load Balancing**

K-mers are distributed to hash tables using suffix bits to ensure even distribution:
- Total hash tables: 2^p (default p=14 → 16,384 tables)
- Distribution key: k-mer & ((1<<p) - 1)
- Expected k-mers per table: total_kmers / 2^p

#### S4. Coverage Threshold Detection Algorithm

**S4.1 Histogram Analysis**

The automatic threshold detection analyzes the k-mer coverage histogram to identify the transition from erroneous to genuine k-mers:

```
Coverage | Count  | Analysis
---------|--------|----------
1        | 150000 | Error peak (skip)
2        | 75000  | Decreasing ↓
3        | 35000  | Decreasing ↓
4        | 40000  | Increase detected! → Threshold = 4
5        | 45000  | Signal region
```

**S4.2 Robustness Measures**

- Minimum decrease streak: 1 (configurable)
- Noise filtering: Skip coverage = 1
- Fallback: If no increase detected, use coverage = 1

#### S5. Bootstrap Implementation Details

**S5.1 K-mer Universe Sampling**

Bootstrap replicates are generated by:
1. Creating a pool of all unique k-mers across samples
2. Sampling with replacement to create bootstrap universe
3. Intersecting each sample's k-mers with bootstrap universe
4. Recalculating distances on filtered k-mer sets

**S5.2 Consensus Tree Construction**

Custom consensus algorithm when majority_consensus unavailable:

```python
def simple_consensus_tree_with_supports(bootstrap_trees, ids):
    reference_tree = bootstrap_trees[0].copy()
    bipartition_counts = {}
    
    for tree in bootstrap_trees:
        for node, bipartition in get_bipartitions(tree):
            if bipartition in bipartition_counts:
                bipartition_counts[bipartition] += 1
            else:
                bipartition_counts[bipartition] = 1
    
    # Annotate reference tree with support values
    for node, bipartition in get_bipartitions(reference_tree):
        if bipartition in bipartition_counts:
            node.support = bipartition_counts[bipartition] / len(bootstrap_trees)
    
    return reference_tree
```

**S6.2 Batch Processing Script**

```bash
#!/bin/bash
# Process multiple FASTA files in parallel

THREADS=16
KMER_SIZE=31
TOP_KMERS=10000

# Generate fingerprints in parallel
ls *.fasta | parallel -j $THREADS \
    "./fgr2 -k $KMER_SIZE -N $TOP_KMERS -t 4 -o {.} {}"

# Run similarity analysis
python calculate_similarity.py -o all_samples_comparison

# Generate individual pairwise comparisons
for file1 in *.fgr2; do
    for file2 in *.fgr2; do
        if [[ "$file1" < "$file2" ]]; then
            base1=$(basename $file1 .fgr2)
            base2=$(basename $file2 .fgr2)
            mkdir -p pairwise_results
            python calculate_similarity.py \
                -o pairwise_results/${base1}_vs_${base2} \
                $file1 $file2
        fi
    done
done
```

### Supplementary Discussion

**S7.1 Comparison with Alignment-Based Methods**

While our k-mer based approach offers significant speed advantages, alignment-based methods remain superior for:
- Detecting small-scale variations (SNPs, small indels)
- Precise breakpoint identification in structural variants
- Detailed evolutionary distance calculations

Our method complements rather than replaces alignment-based approaches, serving as a rapid screening tool or when exact base-level resolution is unnecessary.

**S7.2 Choice of Minimal Hash Selection**

We chose minimal hash selection over alternatives like:
- Random sampling: Less consistent between similar sequences
- Frequency-based selection: Biased towards repetitive elements
- Positional sampling: Sensitive to structural variations

Minimal hash provides theoretical guarantees on Jaccard estimation accuracy while maintaining consistency.

**S7.3 Memory-Speed Trade-offs**

The number of hash tables (2^p) presents a classic memory-speed trade-off:
- Fewer tables: Less memory, more collisions, slower insertion
- More tables: More memory, fewer collisions, faster insertion

Our default (p=14) balances these for typical workloads, but users can adjust based on available resources.
